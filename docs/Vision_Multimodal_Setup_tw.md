# 模型文件夾結構：視覺模型與自動生成的 presets.ini

**一句話：`models\` 下的每個模型都放進自己的子文件夾。** 這一條規則同時解決兩個問題：

1. 視覺（多模態）模型悄悄退化成純文字模式。
2. 模型在自動生成的 `presets.ini` 裡沒有條目（沒有實測的 `ctx-size`，也沒有採樣參數）。

## 問題一：視覺模型退化成純文字

用 **router 模式**（以 `--models-dir` 啟動，本啟動器就是這樣做的，可以熱切換多個模型）運行 `llama-server` 時，如果視覺／多模態的 GGUF 模型沒有正確擺放，它會**悄悄退化成純文字模式**，不會有任何錯誤提示：服務器只是不接受圖片輸入，`/props` 端點會顯示該模型 `"modalities": { "vision": false }`。

這**不是啟動腳本本身的錯誤**，而是 llama-server router 模式發現多模態投影器文件的機制就是這樣設計的。

### 根本原因

在 llama.cpp 裡，支持視覺功能的模型其實是**兩個獨立的 GGUF 文件**：

1. 主要的語言模型（例如 `Qwen3-VL-8B-Q4_K_M.gguf`）
2. 多模態投影器（**mmproj**）文件，負責把圖片編碼成 embedding（例如 `mmproj-Qwen3-VL-8B-F16.gguf`）

在 router 模式下，llama-server 會掃描 `models` 文件夾，並自動把這兩個文件配對，**但必須同時滿足以下兩個條件**：

- 主模型文件和對應的 mmproj 文件**一起放在同一個獨立的子文件夾裡**（不能散放在 `models` 根目錄，也不能和其他模型的文件混在一起）
- 投影器文件名**必須以 `mmproj` 開頭**

只要有一個條件不符合，mmproj 文件就會被忽略，或被誤判成一個無關、無法使用的獨立「模型」，而實際的語言模型則以純文字模式加載。

## 問題二：放在根目錄的模型沒有自動生成的 presets.ini 條目

啟動器會幫你生成 `presets.ini`：量出這張顯卡能容納的最大 `ctx-size`，並按模型家族填好採樣參數。但生成器**只掃描 `models\` 下的子文件夾**：每個子文件夾裡取最大的非 mmproj `.gguf` 當模型，並配對旁邊的 `mmproj*.gguf`。

所以**直接放在 `models\` 根目錄**的單文件模型是這樣的：

| | 模型在自己的子文件夾 | 模型散放在 `models\` 根目錄 |
|---|---|---|
| 出現在 Web UI 的模型列表 | 是 | 是 |
| 在 `presets.ini` 裡有區段 | 是 | **否** |
| 實測的 `ctx-size` | 有 | **沒有**（退回顯存檔位值或 `--fit`） |
| 模型家族採樣參數 | 有 | **沒有**（用服務器默認值） |
| mmproj 配對（視覺） | 是 | **否** |

如果 `models\` 下只有散放的文件，就完全不會生成 `presets.ini`。模型照樣能運行，所以這個問題很容易被忽略：只是用不上調好的參數。

## 正確的目錄結構

```
models/
├─ Qwen3-14B/                                    ← 純文字模型：也放進自己的文件夾，這樣才有 presets.ini 條目
│  └─ Qwen3-14B-Instruct-Q4_K_M.gguf
│
├─ Qwen3.8-27B/                                  ← 視覺模型：必須有自己的文件夾
│  ├─ Qwen3.8-27B-Q4_K_M.gguf
│  └─ mmproj-Qwen3.8-27B-F16.gguf
│
└─ Qwen3-VL-8B/                                  ← 另一個視覺模型，也要有自己的文件夾
   ├─ Qwen3-VL-8B-Q4_K_M.gguf
   └─ mmproj-Qwen3-VL-8B-F16.gguf
```

文件夾名會成為 `presets.ini` 裡的區段名，也是 Web UI 裡顯示的模型名。

## 常見錯誤

| 錯誤做法 | 結果 |
|---|---|
| 主模型 `.gguf` 和 `mmproj-*.gguf` 都直接丟在 `models/` 根目錄 | 無法配對：模型以純文字模式加載，也不會生成 `presets.ini` 區段 |
| 純文字模型直接放在 `models/` 根目錄 | 能加載運行，但沒有實測的 `ctx-size` 和採樣參數 |
| 兩個不同的模型（或同一個模型的兩個量化版本）放在同一個文件夾 | 生成器只取該文件夾裡最大的非 mmproj `.gguf` 當模型，另一個被跳過；router 也可能把 mmproj 配給錯誤的文件 |
| 投影器文件名沒有以 `mmproj` 開頭（例如改成 `vision-encoder.gguf`） | 完全不會被識別為投影器 |
| 主模型和 mmproj 分別放在不同的子文件夾 | 無法跨文件夾配對：router 只會在**同一個文件夾內**尋找配對 |

## 如何確認生效

1. 重新啟動啟動器，查看啟動日誌。`Loaded N custom model presets` 裡的 N 應該大於等於 1（N=0 表示沒有任何區段名匹配到模型）。
2. 打開生成的 `presets.ini`：每個模型都應該有一個 `[文件夾名]` 區段，裡面有 `model =` 行，視覺模型還有 `mmproj =` 行。
3. 視覺模型加載完成後，查看 router 的 `/props`（或 `/props?model=<模型名稱>`）端點，確認出現：
   ```json
   "modalities": { "vision": true }
   ```
4. 在網頁界面中選擇具備視覺能力的模型後，聊天輸入框旁應該出現圖片上傳／附件圖標。如果沒有出現，說明配對失敗。

如果你移動或替換了模型，下次啟動時啟動器會自動重新生成 `presets.ini`（舊文件另存為 `presets.ini.bak`）。

## 快速檢查清單

- [ ] `models/` 下每個模型（不論是否視覺模型）都有**自己獨立的子文件夾**
- [ ] 每個子文件夾裡**只放**這個模型的文件和對應的 mmproj 文件（不混入其他模型的文件）
- [ ] 投影器文件名**以 `mmproj` 開頭**
- [ ] `presets.ini` 裡每個模型都有對應的 `[文件夾名]` 區段
- [ ] 重新啟動後，`/props` 顯示視覺模型 `"vision": true`
